# Windows에서 iPhone·iPad 개인 테스트 앱 설치

0.5.1은 재서명 과정에서 App Group과 공통 Keychain Sharing이 사라져도 화면 QR로 방송 확장에 연결 설정을 전달하도록 구현했습니다. 공유 저장소가 실제로 허용된 설치는 기존 경로도 유지합니다. 공유 권한을 새로 부여하거나 iOS 동의를 생략하는 방식이 아닙니다.

설치 안내: https://reelproof-mobile.vercel.app/ios-personal.html
다운로드: https://reelproof-mobile.vercel.app/downloads/reelproof-ios-personal.ipa?v=0.5.1

이 IPA는 macOS Actions에서 컴파일하며 Apple 인증서·로그인·기기 UDID·Gemini 키를 포함하지 않습니다. 임시 코드 서명은 본인 iPhone 설치용 서명이 아닙니다. Windows에서 본인 계정으로 개발용 서명해야 하며 무료 계정은 보통 7일마다 갱신해야 합니다.

## 서명·설치

1. https://sideloadly.io 에서 Windows 버전을 설치하고 공식 드라이버·Apple 소프트웨어 조건을 따릅니다.
2. iPhone을 USB로 연결하고 ‘이 컴퓨터를 신뢰’를 허용합니다.
3. IPA를 Sideloadly에 넣고 본인 Apple 계정으로 설치합니다. 갱신은 같은 계정과 Bundle ID로 합니다. 로그인·비밀번호·인증 코드는 설치 도구에서 직접 입력하고 채팅에 보내지 않습니다.
4. **앱과 ReplayKit 방송 확장을 함께 유지합니다.** QR 방식에는 App Group·공통 키체인이 필요하지 않습니다. 확장 자체를 제거하면 방송 기능을 사용할 수 없습니다.
5. iPhone이 요구하면 개발자 앱 신뢰와 설정 → 개인정보 보호 및 보안 → 개발자 모드를 확인합니다.

## 탐지 준비 → 방송 시작 확인 → 릴스 시청

1. 처음에 앱에 검증 서버 주소와 원본 접근 키를 입력합니다. Gemini 키나 `REELPROOF_APP_TOKEN_SHA256` 해시는 앱에 넣지 않습니다.
2. **탐지 준비**를 누르면 결과 알림 권한을 요청하고 연결을 준비한 뒤 iOS 방송 창을 엽니다. **iOS의 ‘방송 시작’ 확인은 직접 눌러야 합니다.** 자동으로 창이 열리지 않으면 앱 화면의 시스템 녹화 버튼을 누릅니다.
3. **‘탐지 중 · 영상·기사 화면을 보세요’**로 바뀌면 릴스·쇼츠 앱으로 이동합니다. 별도의 카메라 스캔은 필요하지 않습니다. 공유 저장소가 없으면 자동 연결 중 코드가 잠깐 보일 수 있으며 방송 확장이 그 화면을 읽습니다.
4. 앱은 화면·음성에서 검증할 주장을 선별하고 원문 대조 결과를 알립니다. 근거가 뒷받침함·원문과 충돌함·판별 불가를 구분합니다. 영상 전체의 진위를 이분법으로 확정하지 않습니다.
5. 종료는 제어 센터의 화면 녹화 중지입니다. 자동 연결 키는 최대 30분 동안 유효하며 만료되면 새로 준비합니다.

연결 준비만으로 ‘탐지 중’이라고 표시하지 않습니다. 실제 방송 확장의 시작·종료 신호를 받고 상태를 바꿉니다. 상태 신호에는 키·주장·오디오가 없으며 임의 세션 ID로 현재 방송을 구분합니다. App Group·공통 키체인 없이 Darwin 알림으로 전달합니다. 앱을 다시 열었을 때 방송 상태도 요청합니다.

QR에는 원본 앱 접근 키나 Gemini 키를 넣지 않습니다. 임시 키도 유효 시간 동안 검증 권한을 가지므로 연결 화면을 공유하지 마세요. 세션은 일회용이라고 보장하지 않습니다. 고정된 프로덕션 서버에서 서명을 확인하기 전에는 화면 문자·음성을 업로드하지 않습니다. 다른 영상의 임의 서버 QR은 허용하지 않습니다.

## 빌드 재현

`.github/workflows/ios-personal.yml`은 macOS/Xcode에서 기기용 앱과 확장을 컴파일하고 QR 이미지 생성 → 2x/3x 화면 렌더링 → Vision 해독, 서명 메타데이터, 별도 프로세스의 상태 신호 전달, iOS Simulator의 준비 버튼·시스템 버튼 동작을 검사합니다. Windows용 소스 ZIP에는 `reelproof-personal/` 폴더와 해당 경로에 맞춘 workflow가 포함됩니다.

Actions의 `ReelProof-personal-IPA-requires-your-signature` artifact 안에 실제 IPA와 `build-report.json`이 들어갑니다. 빌드 실패를 설치 성공으로 표시하지 않습니다. 같은 저장소에서는 같은 개인 Bundle ID를 사용합니다. Apple 계정이나 비밀 키 없이 컴파일하며 유료 사용 설정을 자동으로 켜지 않습니다.

## 검증 범위

실제 iPhone의 Sideloadly 재서명·방송 창 표시·자동 연결·다른 앱 화면·음성 캡처·알림은 물리 기기 확인이 별도로 필요합니다. 시뮬레이터와 QR 픽셀 테스트는 실제 ReplayKit 방송 성공의 증거가 아닙니다. 앱별 캡처 보호가 있으면 추출할 수 없습니다.

검증 원문 색인은 WHO 100개·NASA 20개·FEVER 2개입니다. Google 검색은 별도 공급자 한도를 적용받습니다. Gemini API 키는 검증 서버의 Production Secret에만 등록합니다. AI 대본 문체 알림은 실험 신호이며 영상 제작 출처나 진위 확률이 아닙니다.

## 결과 알림이 오지 않을 때

앱의 **탐지 진행 확인**을 펼치면 현재 방송의 화면·자막·음성 수신, 주장 선별, 자막·음성 서버 요청과 응답, 알림 요청 상태가 표시됩니다. 상태 복사에는 키·원문 주장·오디오가 포함되지 않습니다. 앱을 다시 열면 방송 확장에 현재 상태를 요청합니다.

**알림 테스트**를 누른 뒤 다른 앱으로 이동해 배너를 확인합니다. 설정 → 알림 → ReelProof의 알림 허용·배너와 집중 모드·알림 요약을 확인하세요. 시스템이 요청을 접수한 상태와 배너가 실제 표시되는 상태는 다릅니다. 테스트 알림은 사실 검증 결과가 아닙니다.

0.5.1은 화면 전체 점수 대신 문장별로 기존 임계값을 적용합니다. 자막과 음성은 독립적으로 요청하며 각 처리 중에는 최신 대기 내용을 유지합니다. 실패한 자막은 재시도할 수 있고, 선별되지 않은 경우·서버 오류·검증 결과를 구분합니다. 결과에는 해당 주장을 표시해 다음 릴스의 결과로 오해하지 않게 합니다. 검증 시간 제한과 음성 수집 길이는 유지하며 모든 릴스가 끝나기 전 결과를 보장하지 않습니다. 회귀 검사는 실제 선별 모델과 요청 대기를 검사하며 모델 정확도나 물리 기기의 지연 시간을 측정한 결과가 아닙니다.

## 0.5.1: 완료된 주장부터 알림과 저장된 연결 재사용

서버는 최대 3개 주장을 순서대로 끝낸 뒤 응답하던 대신, 기존 동시 처리 한도 2개 안에서 검증하고 원문 대조가 끝난 주장부터 NDJSON으로 전송합니다. 방송 확장은 완전한 주장 결과를 받을 때 바로 알림을 요청합니다. 미완성 모델 출력이나 영상 전체의 잠정 판정을 보내는 방식이 아닙니다. 이후 요청이 실패하면 이미 끝난 주장과 아직 완료하지 못한 주장을 구분합니다. 기존 JSON API도 유지합니다.

같은 정확한 주장과 검색 방식은 같은 서버 인스턴스에서 진행 중인 작업을 공유합니다. 실패는 캐시하지 않으며 한 요청 취소가 다른 요청의 결과를 취소하지 않습니다. 서버리스 인스턴스 사이에는 공유 캐시가 없으므로 전체 서비스 중복 제거를 보장하지 않습니다. 모델·정확한 원문 인용 검사·제한 시간·8초 오디오 수집은 유지합니다.

기본 화면에서 키 입력을 생략하고 저장된 연결을 재사용합니다. 기존 앱을 삭제하지 말고 같은 Apple 계정과 Bundle ID로 덮어 설치하세요. 최초 설치·앱 삭제·키 만료 때에는 ‘연결 설정’에서 연결을 설정해야 합니다. 인증을 없애거나 공개 IPA에 접근 키·공급자 키를 넣지 않습니다.

## 0.5.1: 유튜브·뉴스 기사 내용에서 주장 추출

앱에서 **유튜브·기사 링크로 확인**을 열고 공개 HTTPS 링크를 붙여 넣습니다. 유튜브는 지정 위치부터 60초 구간을 Gemini가 전사·읽기 하며, 기사는 공개 본문을 읽습니다. 원문에 있는 인용문만 최대 3개 주장으로 선별하고 C 순차탐색/최신 검색을 통해 다른 원문과 대조합니다. 입력한 자료 자체는 확인 근거에서 제외합니다. 추출한 내용·선별 주장·근거·개별 오류를 화면에 표시합니다. 화면을 열어 두세요.

유튜브는 전체 영상이 아니라 선택 구간이며, 기사 본문은 최대 24,000자를 사용하고 범위를 표시합니다. 읽을 수 있는 허용 사이트만 지원합니다. 로그인·유료·비공개·삭제·접근 차단 콘텐츠를 우회하지 않습니다. Google 검색·모델 사용 한도에 걸린 주장은 미완료이며 다른 주장 처리는 계속합니다. 미완료는 사실·거짓 판정이 아닙니다.

실시간 탐지는 기존 **탐지 준비 → iOS 방송 시작** 경로를 사용합니다. 유튜브·릴스·기사 화면의 보이는 글자와 허용된 앱 음성을 읽으며 다른 앱의 비공개 데이터나 화면 밖 본문을 직접 읽지 않습니다. 화면의 줄바꿈 문장 선별을 보완했습니다. 링크 검증에는 화면 방송이 필요하지 않으며 서버 접근 키는 저장된 연결을 재사용합니다.

웹사이트의 **유튜브·뉴스 기사 링크 검증**에서도 같은 서버를 사용합니다. 웹페이지는 다른 앱의 화면·재생 소리를 자동 읽지 않습니다.

## 0.5.1: 자체지식 추정 모드

현재 운영 설정은 `VERIFICATION_MODE=knowledge_only`, `WEB_SEARCH_ENABLED=0`입니다. 기사·영상에서 내용을 추출한 뒤 Gemini 내부 지식으로만 판단합니다. Google 검색·RSS 검색·FEVER/LightRAG 근거 조회는 이 모드에서 호출하지 않습니다. 기존 근거 검증 코드는 별도 모드로 남아 있으나 현재 사용하지 않습니다.

결과는 `knowledge_assessment.assessment`의 LIKELY_TRUE / LIKELY_FALSE / UNCERTAIN을 AI 추정으로 표시합니다. 외부 확인이 없으므로 기존 `verdict`는 NOT_ENOUGH_INFO, evidence는 빈 배열이며 근거를 만들어 내지 않습니다. 새 앱은 별도의 AI 추정 제목을 표시합니다. 이전 앱도 설명에 AI 추정 결과가 표시되지만 제목은 판별 불가일 수 있습니다.

Gemini 생성·영상/기사 추출·음성 전사·임베딩 API 요청은 같은 서버 작업자에서 시작 간격을 최소 4초로 제한합니다. 자체지식 모드에서는 근거 검색용 임베딩을 호출하지 않습니다. 서버리스 작업자 간 공유 제한기는 없으며 Gemini 프로젝트 자체 사용 한도는 유지됩니다. 같은 공개 링크 추출과 판단은 짧은 캐시로 중복 요청을 줄입니다.
